Prerequisites

System Requirements

What you need before installing machina

Hardware

  • ● x86_64 processor with VT-x / AMD-V (hardware virtualization)
  • ● 2 GB RAM minimum (4 GB+ recommended for running VMs)
  • ● 20 GB free disk space for images and backups
  • ● KVM kernel module loaded (lsmod | grep kvm)

Software

  • ● Linux with KVM support (kernel 5.x+)
  • ● libvirt + QEMU installed and running
  • ● Rust toolchain (rustup, cargo)
  • ● Node.js 18+ and npm (for web UI build)
  • ● make, gcc, pkg-config, libvirt-dev

Install

Installation

Four paths — pick the one that fits your workflow

1 Automated Install (Recommended)

Single command that detects your distro, installs dependencies, builds from source, and runs 15 verification tests.

$ git clone https://github.com/zyvorailabs/machina.git
$ cd machina
$ sudo ./install.sh

✓ Rust toolchain found
✓ Node.js 20.x detected
✓ Building core library...
✓ Building daemon...
✓ Building web frontend...
✓ 15/15 verification tests passed
✓ machina-daemon.service started on port 5092

2 Make Build + Deploy

Standard Makefile workflow for developers who want more control.

# Build release binaries + web
$ make all

# Install and start service
$ sudo make deploy

3 Deploy Tool

Use the machinactl utility for build and deployment in one step.

# Build and deploy
$ ./machinactl deploy

# Check status
$ systemctl status machina-daemon

4 Remote host (rsync + build on server)

Nothing compiles on your laptop: scripts/deploy-remote.sh rsyncs the repo to the host and runs sudo install.sh there (Rust + npm on the server). Always pass USER then HOST or user@host.

$ ./scripts/deploy-remote.sh operator@10.0.0.5 --bind 0.0.0.0 --open-firewall

# Optional: after rsync, compile only (fast smoke before full install)
$ ./scripts/deploy-remote.sh operator@10.0.0.5 --remote-check
$ ./scripts/deploy-remote.sh operator@10.0.0.5 --remote-build

Getting Started

First Steps

From install to your first running VM in four steps

1

Open the Web UI

Navigate to http://localhost:5092 in your browser. The web interface loads instantly -- no additional services needed.

# Or from a remote machine
http://<your-host-ip>:5092
2

Login with System Credentials

machina uses PAM authentication. Log in with your Linux username and password. No separate accounts to create.

Username: Your Linux user • Password: Your system password

Sessions persist via secure cookies. API tokens (mach_ prefix; legacy vs_ until rotated) available for automation.

3

Create Your First VM

Open Create VM: install from ISO, URL, PXE, or curated virt-install OS presets; clone from a golden qcow2; or run Golden Forge to build a reusable image on the host — Linux via Packer/QEMU, Windows 10/11 via dockur/Podman when enabled (logs + timeline, same pattern as Jobs). Use Disk images to list pools and start virt-image-build jobs. machina validates inputs in real time.

# Or via API
$ curl -X POST http://localhost:5092/api/v1/vms \
  -H "Content-Type: application/json" \
  -d '{"name": "my-first-vm", "vcpus": 2, "memory_mb": 2048, "disk_gb": 20}'

{"status": "created", "name": "my-first-vm"}
4

Access the VM Console

Click the console icon on your VM. machina auto-detects the graphics type and opens the appropriate viewer (VNC, SPICE, or serial).

VNC

Graphical desktop via noVNC

Serial

Text console via xterm.js

SSH

Remote shell via xterm.js

Web UI Overview

Full-featured management interface built with React 19 and Tailwind CSS 4

💻

Dashboard

Real-time host metrics: CPU, memory, disk usage. VM count by state. Recharts time-series graphs. System alerts.

⚙

VM Management

List, create, start, stop, reboot, delete, resize, clone. Inline actions with confirmation dialogs. Batch operations.

Snapshots

Create, list, revert, delete snapshots per VM. Scheduled snapshot support. Snapshot comparison view.

🌐

Networks

Virtual networks with NAT, bridge, isolated modes. DHCP configuration. IP range management. Lease viewer.

💾

Storage

Storage pools and volumes. Create qcow2/raw disks. Resize volumes. Pool capacity bars with usage breakdown.

📦

Backups

Full VM backup and restore. Per-VM filtering. NFS target support. Scheduled backups via systemd timer.

📋

Jobs

Background work: virt-image-build, Golden Forge (Packer Linux or dockur Windows golden qcow2), streamed VM create. Live logs, step timelines, and /jobs/{id} detail.

Config

Configuration

TOML-based configuration with sensible defaults and CLI overrides

Config File: /etc/machina/config.toml

# General settings
[general]
refresh_interval_secs = 5

# Daemon HTTP server
[daemon]
host = "0.0.0.0"
port = 5092

# Libvirt connection
[libvirt]
uri = "qemu:///system"

# TLS (optional)
[tls]
enabled = false
cert_path = "/etc/machina/cert.pem"
key_path = "/etc/machina/key.pem"

# Backup settings
[backup]
backup_dir = "/var/lib/machina/backups"
retain_count = 5

File Locations

What's Next

API Reference

Explore all 100+ REST endpoints with curl examples. Covers VMs, snapshots, networks, storage, advanced operations, guest agent, migration, and more.

# List all VMs
$ curl http://localhost:5092/api/v1/vms

# Get VM metrics

📦

Backup Setup

Configure automated backups with systemd timers. Per-VM backups, NFS target support, disk image inclusion, and retention policies.

# Manual backup
$ ./scripts/backup.sh --vm my-vm --with-disks

# Enable scheduled backups
$ sudo systemctl enable machina-backup.timer
👥

RBAC Configuration

Set up role-based access control with three roles: Admin (full control), Operator (VM lifecycle), and ReadOnly (monitoring only). Assigned via system groups.

Admin: full access Operator: lifecycle ops ReadOnly: view only
📈

Prometheus Integration

Scrape metrics from the built-in Prometheus endpoint. Import the included Grafana dashboard for real-time VM monitoring.

# Prometheus scrape config
- job_name: 'machina'
  static_configs:
  - targets: ['localhost:5092']
  metrics_path: '/api/v1/prometheus'
